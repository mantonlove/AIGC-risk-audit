## 2026-09-17 · 改写优先级重排（P1↔P3）

**原状**：`references/rewrite-rules.md` 的优先级顺序为
P0 清理 → P1 补具体性 → P2 补作者立场 → P3 改节奏 → P4 换术语 → P5 补引语。
该顺序是**按经验排的**，且在 `measured-baseline.md` 里明确声明
"改写建议尚未经过能否降低检测分数的验证"。

**改动**：改为
P0-a 清理 → **P0-b 补具体性（事实锚定）** → P1 补作者立场（标注"不降分"）
→ P2 改节奏（标注"不改变检出分数"）→ P3 换术语 → P4 补引语。

**原因**：完成了原先未完成的改写实验。

**证据**：`references/edit-effects.md`；原始数据 `out/edit_effects.json`；
复现脚本 `tests/measure_edits.py`。n=120 对，3 检测器，配对差 + bootstrap CI + McNemar。

**关键数字**：
- 事实锚定：三检测器 Δ 全为负，符号一致 59–71% → 可用
- 自我设限：d_hello −0.263 但 d_cmj **+0.069**（p=0.0078）、d_zhv3 **+0.046** → 反噬
- 只调节奏：|Δ| ≤ 0.03，符号一致 31% → 噪声

## 2026-09-17 · 新增 anchor.py（事实锚定工具）

**原因**：实测显示"补真实信息"是唯一有支持的动作，但原 skill 只有散文建议，
没有可执行入口，也无法核对用户改完之后具体性有没有提高。

**改动**：新增 `scripts/anchor.py` + `tests/regression.py`（24 条）+ `tests/mutation.py`
（13 处突变，100% 覆盖）。

**边界**：该脚本只**列出**待补真实信息的位置，不生成内容 —— 编造数据/文献是学术不端，
比高 AIGC 率严重。
